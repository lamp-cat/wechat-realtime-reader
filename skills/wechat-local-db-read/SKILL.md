# 读取本机微信消息数据库(只读 / 只收)

用途:在一台 **macOS** 机器上,只读地读取**本机微信 4.x** 的本地消息库(会话、消息、联系人、群、图片),供其它 agent 查询或做下游处理。

## 铁律(任何步骤都不得违反)
- **只读、只收。** 全程只读微信本地数据库,**绝不**提供任何向微信发送消息的通道。
- **不改微信、不关 SIP。** 不修改官方微信 App、不改其签名;系统完整性保护(SIP)保持开启。
- **机密只存本地。** 解密密钥、网关/服务令牌只写入权限 `0600` 的本地文件;在任何聊天、接口返回、日志里一律**打码**,绝不明文打印。
- **回环调用绕过系统代理。** 访问本机服务用 `127.0.0.1`,httpx 等客户端设 `trust_env=False`,避免走到系统代理(如 `127.0.0.1:7897`)。
- **遇到微信安全提示立即停止**并上报用户。删改前先备份。

## 前置条件
1. 目标机为 macOS(Apple Silicon),微信 4.x 已登录并保持**在线**。
2. 已安装读取器 `wechat-realtime-reader`(Go 单可执行文件),以及一次性抓密钥需要的 Frida。
3. 读取器进程需有 **完全磁盘访问权限(Full Disk Access)**,否则无法读本地库;首次系统弹窗需用户点「允许」。

## 关键路径(按机器填写,值放参数区,勿写死在通用步骤)
- 读取器可执行:`<READER_BIN>`(如 `~/wechat-platform/wechat-realtime-reader/bin/wechat-reader`)
- 源配置:`<CONFIG_DIR>/source-config.json`,含 `wxid`、`db_base_path`(微信 `db_storage` 目录)、`vault_dir`
- 机密(0600):`<CONFIG_DIR>/keys.json`(各库解密密钥)、`<CONFIG_DIR>/image-key.json`(图片 .dat 解密密钥)
- 服务令牌(0600):读取器 token 在 `<VAULT_DIR>/state/web-token`

## 一次性:抓取数据库解密密钥
> 仅首次、或微信大版本更新后导致库无法解密时才需要。
1. 对微信做一份**签名的临时副本**,用 Frida hook 其 PBKDF/CommonCrypto 过程,抓出各本地 SQLite 库的密钥与图片密钥。
2. 把密钥写入 `keys.json` / `image-key.json`,权限设 `600`。**不在聊天/日志里打印密钥。**
3. 验证:对全部库跑一次解密校验,确认都能打开。
4. 之后每次启动**直接复用**已抓密钥,无需再跑 Frida。

## 日常:启动读取服务并查询
1. `doctor`:自检密钥/库是否可解密、依赖是否就绪。
2. `sync`:按需增量解密、同步最新消息。
3. `serve`:在 `127.0.0.1:<PORT>` 起只读 API + 页面 + MCP,**令牌鉴权**(令牌=全量读权限,当机密对待)。
4. 其它 agent 通过本地 API 查询(带 token、`trust_env=False`):
   - 会话列表、某会话消息、联系人/群资料
   - 图片:加密 `.dat` 用图片密钥解密;`wxgf` 原图需 `ffmpeg`,缺失则回退缩略图

## 常见故障与定位
- **全部读取卡住/0 字节**:多为缺「完全磁盘访问权限」或 macOS 隐私弹窗未点允许 → 让用户在 系统设置→隐私与安全性 里给**读取器进程**授权。
- **图片 404 / wrong key**:图片密钥不对 → 重新对已缓存图片推导正确 `image-key.json`(旧的改名备份)。
- **解密失败/库打不开**:多为微信升级换了密钥 → 重跑「抓密钥」流程。
- **接口超时/走了代理**:确认客户端 `trust_env=False`、用 `127.0.0.1`。
- **health 显示正常但同步不动**:别只信健康徽标,查实际 `sync` 日志与磁盘访问权限。

## 保活(可选)
用 launchd LaunchAgent 托管 `serve`(及 `sync`),`launchctl bootstrap gui/$(id -u)` 载入、`kickstart -k` 重启;这样后台进程由自身承载 TCC 授权、应用关闭后仍在。

## 边界
- 单账号。只读、只收,**没有发送路径**。
- 远程查看不在本 skill 范围(由用户自行用跳板/中转实现)。
